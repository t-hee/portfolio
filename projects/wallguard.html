WallGuard

실물 센서 데이터를,
모바일 화면까지 연결하다.

WallGuard는 옹벽 안전 모니터링 시스템의 모바일 앱입니다. ESP32 펌웨어·백엔드·앱 개발을 담당했으며, 테스트 환경에서 실물 센서 데이터의 수신·DB 저장·앱 표시까지 통합 테스트에 성공했습니다.

01 / 프로젝트 배경

현장 점검 사이의
변화를 살펴보기 위해

주기적인 옹벽 현장 점검 사이에는 관찰의 공백이 생깁니다. 팀은 축소 옹벽 모형 실험과 기울기·강우 센싱, 모니터링 앱을 연결하는 학술 프로젝트를 진행했습니다.

소프트웨어에서는 센서 데이터를 수신·저장하고, 옹벽별 계측 이력과 위험 단계·알림을 앱에서 주기적으로 조회하도록 구성했습니다. 토목 실험은 팀 연구이며, 제 개인 기여는 펌웨어·서버·앱 개발입니다.

02 / 팀의 축소모형 실험

모형 실험에서 관찰한 변화

팀 학술 포스터에 기재된 실험 내용입니다. 개인의 단독 실험 성과나 현장 예측 성능을 뜻하지 않습니다.

형상 · 규모별 6개 사례

L형·역L형·역T형 세 형상과 포스터에 기재된 3m·7m 두 규모를 조합한 축소모형 실험입니다.

인공강우와 전도 관찰

포스터는 33–133 mm/hr 인공강우 조건과 6개 중 4개 모형의 전도를 보고합니다. 전도 사례는 두 규모의 L형·역T형입니다.

Y축 변화와 실험 참고값

전도 과정의 뚜렷한 Y축 변화를 관찰하고 0.7°를 실험 참고값으로 제시했습니다.

03 / 개인 기여

장치 · 서버 · 앱을 잇는 개발

개인 소프트웨어 기여를 영역별로 정리했습니다. 토목 축소모형 실험은 팀 연구입니다.

01

ESP32 · 센서 펌웨어

SCL3300 센서 읽기, 시작 시 기준각 보정, 이동평균 처리, 강우 데이터 처리와 JSON 전송을 구현했습니다.

02

FastAPI · DB · 세션 연동

계측 수신, 옹벽·측정 세션 연결, DB 영속 저장, 위험 단계 분류와 데이터 조회를 구현했습니다.

03

WallGuard 모바일 앱

React Native·Expo 앱의 옹벽 관리, 측정 세션, 위험 단계 표시, 이력·그래프, 알림과 API 연동을 구현했습니다.

04 / 데이터 흐름과 구조

계측값을 화면의 정보로

SCL3300-D01 3축 기울기 센서와 강우 센서에서 시작하는 소프트웨어 연동 구조입니다.

  1. 01 / 장치

    ESP32

    센서 읽기 · 기준각 보정 · 이동평균 · Wi-Fi JSON 전송

  2. 02 / 수신 서버

    FastAPI

    계측값 수신 · 활성 세션 연결 · 서버 위험도·알림 처리

  3. 03 / 영속 저장

    PostgreSQL

    SQLAlchemy·Alembic 기반 장치·옹벽·세션·계측·알림 저장 구조

  4. 04 / 모바일 조회

    React Native

    FastAPI를 통해 계측 이력과 상태를 조회하는 WallGuard 앱

ESP32 → FastAPI → PostgreSQL → 앱에서 API로 조회

단일 장치와 활성 측정 세션

펌웨어는 장치 ID를 사용
ESP32는 각 옹벽 ID를 직접 관리하지 않습니다. 옹벽 연결은 서버의 활성 측정 세션이 결정합니다.
장치 하나에 활성 세션 하나
한 ESP32를 여러 옹벽 사이에 옮겨 사용하며, 동시에 하나의 옹벽만 측정 대상으로 연결합니다.
활성 세션이 있는 유효한 수신
계측값을 해당 세션에 저장하며, API는 201 응답을 반환할 수 있습니다.
활성 세션이 없는 수신
202 응답으로 처리하고 계측값은 저장하지 않는 구조입니다.

05 / 구현 기능

옹벽별 계측과 주기적 모니터링

실물 계측값의 수신·저장·앱 조회를 테스트 환경에서 확인한 모니터링 시스템입니다.

옹벽과 측정 세션 관리

옹벽 등록·조회·수정·삭제와 세션 시작·종료, 활성 세션을 관리합니다.

각도 · 강우 · 위험 단계

X/Y/Z와 강우 데이터를 다루고, 서버가 개발용 임시 기준에 따라 5단계 상태를 판단합니다.

계측 이력 · 알림 조회

옹벽 상세의 이력·그래프와 알림 기록을 조회합니다. 홈·상세 화면은 약 7초 폴링으로 갱신합니다.

06 / 엔지니어링 설계

연결의 기준과 판단 주체를 명확하게

센서 보정과 옹벽 연결의 분리

구성
펌웨어 시작 시 기준각을 보정하고, 서버는 활성 세션으로 측정 대상 옹벽을 지정합니다.
구분
장치의 측정 처리와 옹벽별 데이터 귀속을 별도 역할로 관리합니다.

서버가 판단하는 위험 단계

구성
기준각 대비 X/Y 변화량이 있으면 두 절댓값 중 큰 값을 사용합니다. 변화 추이, 강우와 기울기 증가, 데이터 신선도도 고려합니다.
구분
앱은 서버의 위험 단계를 표시합니다. 펌웨어 진단 상태와 화면의 최종 위험 판단은 구별됩니다.

폴링과 이력을 통한 상태 확인

구성
앱은 약 7초 간격의 폴링으로 상태를 갱신하고, 현재 값과 과거 이력을 함께 다룹니다.
구분
WebSocket·푸시 기반의 즉시 갱신으로 설명하지 않습니다. 지연되거나 끊긴 데이터의 상태도 서버 처리 범위에 포함됩니다.

개발용 임시 위험 단계

대표 기울기별 앱 표시 단계
대표 기울기앱 표시 단계
0.1° 이하안전
0.1° 초과 ~ 0.3° 이하주의
0.3° 초과 ~ 0.5° 이하위험
0.5° 초과 ~ 0.7° 미만한계
0.7° 이상즉각 대응

위 구간은 개발용 임시 값이며, 팀 축소모형 실험의 0.7° 참고값 역시 현장 안전 기준으로 검증된 값이 아닙니다. 실물 데이터 연동 테스트의 성공이 붕괴 예측 성능이나 경보 효과를 보장하지는 않습니다.

08 / 결과와 확장 범위

실물 통합 검증과 경진대회 수상

2026 IoTing Life: 융합 아이디어 경진대회

경상국립대학교 공학교육혁신센터 · 프로젝트 기간 이후 수상

성공한 물리 장치 데이터 연동
실물 ESP32 측정값을 FastAPI가 수신하고 DB에 저장한 뒤 WallGuard 앱에서 조회·표시하는 기능 통합 테스트에 성공했습니다.
운영 배포 · 현장 검증과의 구분
확인된 성과는 테스트 환경의 기능 연동입니다. 운영용 클라우드 배포와 현장 안전성 검증은 별도 범위이며 완료가 확인되지 않았습니다.
영상 · 딥러닝은 향후 확장
CCTV는 학술 포스터 제목에 포함되지만 영상·딥러닝 연계는 향후 확장입니다. 동작하는 CCTV 이상 탐지 기능으로 소개하지 않습니다.
전원 · 클라우드 연동 범위
태양광·배터리·절전 전략은 제안 맥락입니다. 배터리 측정, Deep Sleep 제어, 원격 보정과 전체 클라우드 장치 연동의 완료는 확인되지 않았습니다.
